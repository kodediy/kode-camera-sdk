# The budget of internal RAM for this project, read by tools/check_ram.sh:
#
#   ../../tools/check_ram.sh build/camera_target.elf ram_budget.txt
#
# This project links kode-sdk at v0.1.5 (API v4) with every Camera component on top - both
# layers, camera.h and camera_sys.h - and CONFIG_KODEOS_RADIO=y as every app of the module needs it, so
# what it takes of the ESP32-P4's 640 KB of internal RAM at link time is what an app that uses the module
# starts with. Nearly all of it is kode-sdk's. The module's own statics are the owner's Active Object - its
# stack (8 KB, below) and its queue - and about 3 KB more (the white balance's scratch of 1280 bytes, the
# owner's state, the error texts of four tasks: 576 bytes, the sys layer's doors table). The frame task's
# and the events task's stacks come from the heap when camera_begin() starts them, not at link time, and
# the frame buffers are in PSRAM (docs/guide.md, "What it costs an app").
#
# static_max is the ceiling of that static image - code in IRAM, .data and .bss - with a few KB of room
# above what the project takes. A change that needs more either moves something to PSRAM or raises this number in the same commit, where a reviewer sees it.
static_max 266000
